# AVL Shop - ADSA mini project (web version)

Online shopping product search built on three AVL trees (by ID, by name, by price).
The data structures are written in C++ (`src/shop.cpp`) and compiled to WebAssembly.
The page (`public/index.html`, `style.css`, `app.js`) only draws the interface.

```
shop-web/
├── src/shop.cpp        C++ engine: AVLTree + Store (same logic as the console version)
├── public/             the website - this is the folder Netlify serves
│   ├── index.html
│   ├── style.css
│   ├── app.js
│   ├── shop.js         generated by the build (not written by hand)
│   └── shop.wasm       generated by the build
├── build.sh            build on Linux / macOS / Git Bash
├── build.bat           build on Windows
└── netlify.toml        tells Netlify to publish the public/ folder
```

## 1. Build the C++ to WebAssembly (once, and again after every change to shop.cpp)

Install Emscripten:

```
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk
./emsdk install latest
./emsdk activate latest
source ./emsdk_env.sh        # Windows: emsdk_env.bat
```

Then, in the same terminal, from the `shop-web` folder:

```
./build.sh                   # Windows: build.bat
```

This creates `public/shop.js` and `public/shop.wasm`.

## 2. Test on your computer

The page must be opened through a web server (a browser will not load .wasm from a double-clicked file):

```
cd public
python3 -m http.server 8000      # Windows: python -m http.server 8000
```

Open http://localhost:8000.

## 3. Deploy to Netlify

**Drag and drop (fastest):** open https://app.netlify.com/drop and drop the `public` folder.

**From GitHub:** push the whole `shop-web` folder, including the built `shop.js` and `shop.wasm`. In Netlify choose
Add new site, then Import from Git. Leave the build command empty. `netlify.toml` already sets the publish folder to `public`.

Netlify cannot run Emscripten for you, so the built files must be in the repo.

## Where each lab topic lives

| Feature in the page                | C++ function (src/shop.cpp)          | Complexity    |
|------------------------------------|--------------------------------------|---------------|
| Add product                        | `Store::addProduct` (3 tree inserts) | O(log n)      |
| Search by ID                       | `AVLTree::find`                      | O(log n)      |
| Name starts with                   | `AVLTree::range` on the name tree    | O(log n + k)  |
| Name contains                      | `Store::searchNameContains`          | O(n)          |
| Price range                        | `AVLTree::range` on the price tree   | O(log n + k)  |
| Change price                       | `Store::updatePrice` (erase + insert)| O(log n)      |
| Remove                             | `Store::removeProduct`               | O(log n)      |
| Sorted list                        | `inorder` / `reverseOrder`           | O(n)          |
| AVL trees tab                      | `AVLTree::toJson`                    | O(n)          |
| Balance demo                       | `balanceDemo`                        | O(n log n)    |

The viva questions in the original README (why AVL, why three trees, why a composite key) apply unchanged.
